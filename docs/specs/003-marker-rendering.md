# 003 标记渲染（F3）设计规格

- **日期**：2026-08-16
- **状态**：已定稿
- **来源**：`docs/requirements.md` F3；spec 002（检测引擎）

## 背景与目标

把检测引擎的判定结果变成用户可见的东西：在直播间聊天区，被判定异常的用户所发弹幕的昵称旁出现标记，鼠标悬停显示判定类别、置信度与证据。成功标准：构造判定后，该用户的新弹幕即时带标记、其在屏旧弹幕补标，悬停 tooltip 内容正确，不破坏聊天区原有布局与交互。

## 已拍板决策

| # | 决策 | 拍板人 | 日期 |
|---|------|--------|------|
| 1 | 标记形态为昵称旁的行内小徽章（每条命中规则一枚），不做整条弹幕高亮 | 用户 | 2026-08-16 |
| 2 | 悬停提示 MVP 用原生 `title` 属性；F4/F5 落地需要可交互内容时升级为自定义浮层，内容生成与呈现分层保证只动呈现层 | 用户 | 2026-08-16 |
| 3 | 样式经一个 `<style>` 标签注入，类名统一 `lj-` 前缀，不用 Shadow DOM（徽章需融入 B 站行内流） | AI（实现细节自主权内） | 2026-08-16 |
| 4 | 判定→徽章文案/配色的映射为纯函数并配单元测试；DOM 胶水层保持极薄，人工目视验收 | AI（实现细节自主权内） | 2026-08-16 |

## 设计

### 徽章映射（mark/badge.ts，纯函数）

- 输入 `UserVerdict`，输出徽章描述数组：每枚 `{ rule, label, color, title }`。
- 配色：D1 橙、D2 红、D4 紫；置信度体现为实心（high）/ 半透明（medium）。
- `title` 内容：规则名 + 置信度 + 证据逐行。

### DOM 胶水（mark/marker.ts）

- `ensureStyle()`：首次使用时注入 `<style>`（`lj-` 前缀类，行内徽章、圆角、字号 10px、不抢布局）。
- `markElement(el, verdict)`：在弹幕节点昵称区前插入/更新徽章容器（`data-lj-marker` 幂等：已存在则更新内容，判定升级时刷新）。
- `markExisting(uid, verdict)`：补标该用户在屏旧弹幕（按 `.chat-item.danmaku-item[data-uid]` 反查）。
- B 站聊天区自行裁剪旧节点，徽章随节点自然消亡，无需清理。

### 接线（main.ts）

- 每条弹幕事件：ingest 后查 `engine.getVerdict(uid)`，命中且事件带 `el` 则 `markElement`。
- `onVerdict` 回调：`markExisting(uid, verdict)` 补标旧弹幕；保留控制台 JSON 输出（调试期）。
- 自己的弹幕同样标记（不特殊豁免）。

### 目录结构

```
src/lib/mark/
  badge.ts     判定 → 徽章描述（纯函数）
  marker.ts    DOM 注入与幂等更新
test/mark/     badge 映射单元测试
```

## 明确不做（out of scope）

- 自定义悬停浮层、点击徽章展开详情/弹幕记录（属 F4 的交互）。
- 标记样式用户配置（属 F7 设置面板；配色先硬编码）。
- 处置按钮（举报/拉黑/禁言，属 F5）。
- 对历史弹幕的持久化补标（页面刷新即重置，属 F4）。

## 验收标准

- `bun test`、`bun run typecheck`、`bun run lint`、`bun run build` 全绿。
- 人工检查清单（视觉产物必须亲眼看）：
  1. 装产物进 Tampermonkey，打开人多的直播间；
  2. 触发判定的用户新弹幕昵称旁出现徽章，配色与规则对应（D1 橙 / D2 红 / D4 紫）；
  3. 悬停徽章显示规则 + 置信度 + 证据；
  4. 判定产生前已在屏的该用户旧弹幕被补标；
  5. 聊天区布局无错位、原有交互（右键菜单、滚屏）正常。
