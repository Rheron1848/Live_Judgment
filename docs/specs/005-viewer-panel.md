# 005 查看面板与名单管理（F4 交互层）设计规格

- **日期**：2026-08-16
- **状态**：已定稿
- **来源**：`docs/requirements.md` F4；spec 004（存储层）；spec 003 决策 2（可交互浮层升级点）

## 背景与目标

给用户一个可交互的查看入口：点击徽章打开用户面板，看到该用户的违规档案（**含在哪些主播房间犯过事**）与弹幕历史，并能加/移出人工名单、清理档案。成功标准：点徽章出面板、档案按时间列出带主播名、名单操作即时反映到徽章、面板样式不受 B 站页面污染。

## 设计

### 入口

- **点击任意徽章**（自动或人工）→ 打开该 uid 的用户面板。徽章上加 `data-lj-uid`，document 级事件委托处理点击。
- **Tampermonkey 菜单**（`GM_registerMenuCommand`，需在 vite.config 加 `@grant`）→ 打开面板到「名单」页，不依赖具体用户。

### 面板（panel/panel.ts + Shadow DOM）

- 固定定位右侧浮层，关闭按钮；标题栏可拖拽移动（2026-08-17 用户要求加入；缩放仍不做）。
  （旧规则「MVP 不做拖拽/缩放」→ 新规则：拖拽做，缩放不做。）
- 两个页签：
  - **用户**：昵称 + uid；违规档案列表（时间、规则徽章、置信度、证据、所在房间——主播名经 `resolveAnchorName` 异步解析，房间号可点击跳转）；弹幕历史（最近 100 条，时间+原文）；操作按钮：[加入/移出人工名单]（可填备注）、[清空该用户档案]。
  - **名单**：全部人工名单条目（昵称、加入时间、来源房间、备注），逐条 [移出]；底部 [清空全部违规档案]（红色，二次确认 `confirm()`）。
- 数据装配为纯函数（`panel/view-model.ts`：incidents/danmaku → 视图模型，含按时间倒序、主播名占位符），配单元测试；DOM 渲染层保持薄。

### 与现有模块的接口变更

- `store/incidents.ts`：新增 `deleteIncidentsByUid(db, uid)`、`clearIncidents(db)`。
- `mark/marker.ts`：新增 `unmarkManual(uid)`（移出名单时清掉人工徽章槽位）；徽章节点加 `data-lj-uid`。
- `main.ts`：装配面板上下文（db、watchlist Map、名单变更回调——变更时同步内存 Map、补标/清标、落库）。

### 目录结构

```
src/lib/panel/
  panel.ts        Shadow DOM 面板：开关、页签、渲染、事件
  view-model.ts   incidents/danmaku → 视图模型（纯函数）
test/panel/       view-model 单元测试
```

## 明确不做（out of scope）

- 面板拖拽/缩放/主题、弹幕记录全文检索与导出。
- F5 处置按钮（举报/拉黑/禁言）——下一规格进面板用户页。
- F6 屏蔽词、F7 设置面板。

## 待决（OPEN）

- 无。

## 验收标准

- `bun test`、typecheck、lint、build 全绿。
- 人工检查清单（视觉产物必须亲眼看）：
  1. 点击自动徽章 → 面板显示该用户档案，含主播名与可点房间链接；
  2. 加入人工名单（填备注）→ 该用户在屏弹幕即时出现「人工」徽章；移出 → 徽章消失；
  3. 清空该用户档案 → 列表变空且 IndexedDB 中对应记录删除；
  4. Tampermonkey 菜单打开名单页 → 条目完整、可逐条移出；
  5. 面板在 B 站深色/浅色主题下均可读，不受页面样式污染（Shadow DOM 生效）。
