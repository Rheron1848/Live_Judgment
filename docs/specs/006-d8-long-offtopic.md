- **日期**：2026-08-17

## 背景与目标

识别「复制粘贴长文灌水」：同一用户连续发出多条**显著长于房间一般弹幕、且与当前聊天上下文无关**的弹幕（典型形态：大段科普/圣经/无关文案粘贴）。成功标准：合成流单测覆盖命中与防误报（正常长评不误判），真实直播间 CDP 验收。

## 设计

### 信号构成（全部满足才命中）

对某用户窗口内最近的消息逐条判定「长文无关」，然后看连续性：

1. **长**：归一化后长度 ≥ 30 字 **且** ≥ 房间滚动中位数长度的 2 倍（房间中位数由全局窗口内消息长度实时维护，初期样本不足时只用绝对阈值）。
2. **无关**：该消息的字符二元组被上下文**覆盖的比例** < 0.05。上下文 = 全局窗口内该用户之外的最近 ≤50 条消息合并文本（剔除自身，防止自己跟自己重复刷相同长文时"有关"——那种归 D1 管）。注意用覆盖度（消息二元组出现在上下文中的比例）而非 Jaccard：上下文集合远大于消息集合，Jaccard 分母被放大后任何消息都"无关"，退化失效。
3. **连续**：窗口内满足 1+2 的消息 ≥ 3 条。

命中置信度**中**；若这些长文之间归一化文本高度相似（既是长文又是复读），置信度升**高**（与 D1 互为佐证，但证据独立记录）。

### 为什么不用真"语义"

语义级相关性判断需要 LLM 或 embedding，超出本地油猴脚本定位（零外呼、零重依赖）。字符二元组对中文是成熟的轻量近似：正常讨论（哪怕是长评）会与上下文共享话题词；粘贴灌水与上下文几乎零共享。预期误报场景：突然的科普长评、点歌歌词——单条不触发（需连续 ≥3 条），置信度仅"中"，供人工复核，符合"概率性标记"定位。

### 实现位置

- `src/lib/detect/rules/d8-long-offtopic.ts`：`checkLongOfftopic(userEvents, globalEvents, cfg)` 纯函数，与 D1/D4 同构。
- `verdict.ts`：`RuleId` 加 `'D8'`；`DetectConfig` 加 `d8` 阈值组（minLen 30、lengthRatio 2、overlapMax 0.05、consecutiveMin 3、contextSize 50）。
- `engine.ts`：接线（把全局窗口传入）。
- `mark/badge.ts`：D8 配色（青色 #009688，与现有三色区分）与规则名。
- `panel/view-model.ts`：规则名映射加 D8。
- `test/detect/`：合成流用例（先红后绿）：
  - 同一用户连发 3+ 条长且零重合文本 → D8 中置信；
  - 长文但内容与上下文共享话题词 → 不命中；
  - 长文只有 1-2 条 → 不命中；
  - 短句连续刷屏 → 不命中（归 D1 的场景不重复计）；
  - 房间中位数动态：全场都在发长文时绝对阈值兜底逻辑正确。

## 明确不做（out of scope）

- LLM/embedding 语义判定、中文分词。
- D8 与 F6 屏蔽词联动（属 F6 规格）。
- 阈值自动调优。
